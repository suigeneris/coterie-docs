# Coterie — CI Setup

**Goal:** every push to `coterie-ios` and `coterie-backend` is verified automatically, at
zero Actions cost.

**Status:** backend pipeline **live and passing** on GitHub. iOS pipeline written and pushed,
but will queue until a self-hosted runner is registered (see Handover).

---

## Decisions

| Decision | Choice | Why |
|---|---|---|
| iOS runner | **Self-hosted** on the dev Mac | GitHub-hosted macOS bills at a 10× multiplier — a 10-minute job costs 100 of the 2,000 included minutes, allowing ~20 runs/month. Self-hosted is free and faster, since Xcode, SPM and simulator caches stay warm. |
| Backend runner | GitHub-hosted `ubuntu-latest` | 1× multiplier. **Measured 2m08s** end to end, so ~3 billed minutes — roughly 660 runs/month inside the 2,000-minute free allowance. Overage is ~$0.008/min. |
| QA/prod Supabase projects | **Deferred** | No pilot audience yet, and hosted projects cost money past the free tier. Migrations are forward-only and portable, so `supabase link` + `db push` will work unchanged whenever they are created. |
| Secrets | **Not yet needed** | Everything is local. The committed anon key is the standard local-dev JWT. Real keys only appear once QA/prod exist. |

## Backend pipeline — `coterie-backend/.github/workflows/db-test.yml`

Runs migrations from scratch and the pgTAP suite on every push and PR.

**Only Postgres is started.** The `auth` schema is created during database init rather than
by the GoTrue container, so all twelve other services are excluded — one image to pull
instead of twelve. Measured locally:

```
supabase start -x <everything but postgres>   17s   1 container
supabase test db                               1s   13/13 PASS
```

`supabase start` applies migrations itself on a fresh volume, so there is no separate
`db reset` step. The CLI version is pinned to `2.112.0` to match local development; bump it
deliberately rather than tracking `latest`.

## iOS pipeline — `coterie-ios/.github/workflows/ci.yml`

Runs `make generate`, `make test`, `make lint` on every push and PR.

Needs no backend: every test runs against mock repositories, and `AppEnvironment` reads
`Info.plist` rather than the network.

The runner daemon does not inherit an interactive shell's `PATH`, so the workflow prepends
`/opt/homebrew/bin` via `$GITHUB_PATH` — without it `xcodegen` and `swiftlint` are not found.

## Handover — one step needing a human

> **Correction:** earlier notes in the Plan 1 doc claimed the missing `workflow` token scope
> would block pushing `.github/workflows/`. That is **not** true for this project. The scope
> restriction applies to token-authenticated pushes over HTTPS; these remotes use the
> `github-personal` **SSH** alias, where no OAuth token is involved. Both workflows pushed
> fine with the token still lacking `workflow`. No `gh auth refresh` is needed.

### Register the self-hosted macOS runner

On the dev Mac, from **Settings → Actions → Runners → New self-hosted runner** in
`coterie-ios`, or via CLI. The registration token is short-lived and must be fetched fresh:

```bash
mkdir -p ~/actions-runner && cd ~/actions-runner
curl -o actions-runner-osx-arm64.tar.gz -L \
  https://github.com/actions/runner/releases/latest/download/actions-runner-osx-arm64-<version>.tar.gz
tar xzf actions-runner-osx-arm64.tar.gz
./config.sh --url https://github.com/suigeneris/coterie-ios \
            --token <registration-token> \
            --labels self-hosted,macOS
./run.sh                 # foreground, or:
./svc.sh install && ./svc.sh start   # background service
```

The workflow targets `runs-on: [self-hosted, macOS]`, so those labels must both be present.

**Consequence to accept:** iOS CI only runs while that Mac is on and the runner is up. Jobs
queue otherwise rather than failing. That is the trade for zero cost.

## Notes

- **Self-hosted security:** the usual warning is that untrusted forks can run arbitrary code
  on your machine. `coterie-ios` is private with a single committer, so there are no
  untrusted forks. Revisit if the repo is ever opened up or gains outside contributors.
- **No untrusted input reaches any `run:` step** in either workflow, so the workflow-injection
  class of bug does not apply. Keep it that way — never interpolate `github.event.*` into a
  shell command.
- **Branch protection is not configured.** The pipelines report status but nothing enforces
  it. Worth requiring both checks on `main` once the runner is live.
- **Node 20 deprecation.** `actions/checkout` was bumped to `v5`. `supabase/setup-cli@v1` is
  still on the older runtime and is force-run on Node 24 by GitHub; it emits a warning, not a
  failure. Bump when upstream ships a newer major.
- **Until the runner is registered, iOS runs queue rather than fail.** A queued run was
  cancelled after the first push to avoid one sitting indefinitely. Expect the same on the
  next push until the runner is up.
